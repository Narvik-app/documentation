# Installation avec docker
Il s'agit de la méthode la plus simple et rapide à faire.

L'image est disponible sur [docker hub](https://hub.docker.com/repository/docker/benoitvignal/narvik-back)

Variables d'environnements à définir :

- front :
  - `NUXT_API_PARTY_ENDPOINTS_LOCAL_API_URL` : Url vers l'api. Non exposé par défaut.
    - Utilisation du dns de docker : `http://php`
  - `NUXT_SESSION_PASSWORD` : Chaine aléatoire
  - `NUXT_OAUTH_CLIENT_ID` / `NUXT_OAUTH_CLIENT_SECRET` : Identifiants du client OAuth principal, créés côté backend par `bin/console install:oauth` (voir [Post-installation](./03.post-installation)).
  - `NUXT_OAUTH_BADGER_CLIENT_ID` : Identifiant du client OAuth `badger` (généré
    automatiquement par `bin/console install:oauth`, voir
    [Post-installation](./03.post-installation)). Ce client est public (sans secret).
- php :
  - `SERVER_NAME`
  - `MERCURE_PUBLISHER_JWT_KEY`
  - `MERCURE_SUBSCRIBER_JWT_KEY`
  - `TRUSTED_PROXIES`
  - `TRUSTED_HOSTS`
  - `DATABASE_URL`
  - `ENCRYPTION_KEY`: String, généré avec : `php -r 'echo base64_encode(sodium_crypto_secretbox_keygen());`
  - `OAUTH_PASSPHRASE`
  - `OAUTH_ENCRYPTION_KEY`
  - `SALES_EMAIL`
  - `EXPOSE_VERSION`: Bool, optionnel

- database :
  - `POSTGRES_DB`
  - `POSTGRES_PASSWORD`
  - `POSTGRES_USER`


## Docker compose
Voici un exemple de docker-compose pour faire fonctionner le projet (backend + frontend).

::: code-group
```yaml [compose.yaml]
name: narvik

# Backend configuration, shared by the php, worker-high, worker and scheduler services
x-narvik-back: &narvik-back
  image: benoitvignal/narvik-back:3
  restart: unless-stopped
  environment:
    SERVER_NAME: php:80
    MERCURE_PUBLISHER_JWT_KEY: ${CADDY_MERCURE_JWT_SECRET:-!ChangeThisMercureHubJWTSecretKey!}
    MERCURE_SUBSCRIBER_JWT_KEY: ${CADDY_MERCURE_JWT_SECRET:-!ChangeThisMercureHubJWTSecretKey!}
    TRUSTED_PROXIES: '*'
    TRUSTED_HOSTS: '*'
    DATABASE_URL: postgresql://${POSTGRES_USER:-app}:${POSTGRES_PASSWORD:-!ChangeMe!}@database:5432/${POSTGRES_DB:-app}?serverVersion=${POSTGRES_VERSION:-15}&charset=${POSTGRES_CHARSET:-utf8}
    # Generate a long random string
    OAUTH_PASSPHRASE:
    OAUTH_ENCRYPTION_KEY:
    ENCRYPTION_KEY: ''
    TURNSTILE_SECRET: ''

    FRONTEND_URL: 'https://narvik.app'
    SALES_EMAIL: 'ventes@narvik.app'

  volumes:
    - app_jwt:/app/config/jwt
    - app_private:/app/private
    - caddy_data:/data
    - caddy_config:/config
  networks:
    - narvik

x-narvik-back-worker: &narvik-back-worker
  <<: *narvik-back
  # Let the worker finish the message being handled
  stop_signal: SIGTERM
  stop_grace_period: 30s
  # The image healthcheck targets the web server, which does not run in the workers
  healthcheck:
    disable: true
  depends_on:
    php:
      condition: service_healthy # database migrations are run by php on startup

services:

  front:
    image: benoitvignal/narvik-front:3
    restart: unless-stopped
    environment:
      # Local container (backend)
      NUXT_API_PARTY_ENDPOINTS_LOCAL_API_URL: http://php
      NUXT_SESSION_PASSWORD: 66de112769b279bceb5c7afb761b2514
      # OAuth client credentials, see the "Post-installation" page for how to obtain them.
      # Server-only, never exposed to the browser.
      NUXT_OAUTH_CLIENT_ID:
      NUXT_OAUTH_CLIENT_SECRET:
      NUXT_OAUTH_BADGER_CLIENT_ID: badger
      # API is hosted on a local network with self-sign certificate, and publicly accessible
      # NODE_TLS_REJECT_UNAUTHORIZED: 0

    ports:
      - 80:3000
    depends_on:
      - php
    networks:
      - narvik

  php:
    <<: *narvik-back
    depends_on:
      database:
        condition: service_healthy

  # Messenger workers and scheduler: same image, another command, see the note below
  worker-high:
    <<: *narvik-back-worker
    command: [bin/console, messenger:consume, async_high, --time-limit=3600, --memory-limit=256M]

  worker:
    <<: *narvik-back-worker
    command: [bin/console, messenger:consume, async_medium, async_low, --time-limit=3600, --memory-limit=256M]

  scheduler:
    <<: *narvik-back-worker
    command: [bin/console, messenger:consume, scheduler_default, --time-limit=3600, --memory-limit=256M]

  database:
    image: postgres:${POSTGRES_VERSION:-15}-alpine
    restart: unless-stopped
    environment:
      POSTGRES_DB: ${POSTGRES_DB:-app}
      # You should definitely change the password in production
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-!ChangeMe!}
      POSTGRES_USER: ${POSTGRES_USER:-app}
    healthcheck:
      test: ["CMD-SHELL", "pg_isready --host=127.0.0.1 --username=\"$$POSTGRES_USER\" --dbname=\"$$POSTGRES_DB\""]
      interval: 5s
      timeout: 5s
      retries: 20
    networks:
      - narvik
    volumes:
      - database_data:/var/lib/postgresql/data:rw
      # You may use a bind-mounted host directory instead, so that it is harder to accidentally remove the volume and lose all your data!
      # - ./docker/db/data:/var/lib/postgresql/data:rw
    # Database port for local debugging
    # ports:
    #   - 5432:5432




volumes:
  app_jwt:
  app_private:

  caddy_data:
  caddy_config:

  database_data:

networks:
  narvik:
    driver: bridge
```
:::

Le backend utilise la même image pour 4 services :

- `php` : l'API. Au démarrage, il exécute les migrations de la base de données.
- `worker-high` : traitements asynchrones prioritaires (envoi des emails).
- `worker` : autres traitements asynchrones (imports, exports, synchronisations).
- `scheduler` : tâches récurrentes (voir [Post-installation](./03.post-installation#taches-recurrentes)), il ne doit y en avoir qu'**une seule instance**.

Les variables d'environnement et volumes sont partagés grâce au bloc `x-narvik-back`.

## Docker compose + Traefik
Pour une meilleure flexibilité, il est recommandé de séparer le docker lié à Traefik du docker liée au projet.

Cela permettra plus tard d'ajouter facilement d'autre projet, par exemple Odoo pour la gestion comptable et gestion de stock.

Les conteneurs accessibles publiquement devront être sur le network `traefik-global-proxy`

Dans le cas où vous copiez les configurations suivantes, des variables d'environnement global ont été définis (`sudo nano /etc/environment`) :

- `NARVIK_SESSION_PASSWORD`
- `NARVIK_POSTGRES_DB`
- `NARVIK_POSTGRES_PASSWORD`
- `NARVIK_POSTGRES_USER`
- `NARVIK_JWT_PASSPHRASE`
- `NARVIK_CADDY_MERCURE_JWT_SECRET`
- `NARVIK_OAUTH_CLIENT_ID`
- `NARVIK_OAUTH_CLIENT_SECRET`

### Configuration de Traefik

::: code-group
```yaml [compose.yaml] {19}
version: "3.6" # important, so that we can name our network

services:
  traefik:
    image: "traefik:v2.11"
    container_name: "traefik"
    networks:
      - traefik-global-proxy
    ports:
      - "443:443"
      - "80:80"
    volumes:
      - "./traefik.toml:/etc/traefik/traefik.toml"
      - "./letsencrypt:/letsencrypt"
      - "/var/run/docker.sock:/var/run/docker.sock:ro"
    # Enable for debugging
    # labels:
    #   - "traefik.enable=true" # enable the dashboard
    #   - "traefik.http.routers.traefik.rule=Host(`<monitor domain>`)" # domain for dashboard
    #   - "traefik.http.routers.traefik.entrypoints=websecure"
    #   - "traefik.http.routers.traefik.tls.certresolver=letsencrypt"
    #   - "traefik.http.routers.traefik.service=api@internal" # points to dashboard

# this is the network that every container should connect to, in order to communicate with Traefik. We give it a nice name to type it easier.
networks:
  traefik-global-proxy:
    name: "traefik-global-proxy"
```

```toml [traefik.toml] {16}
[log]
  level = "ERROR"

[entryPoints]
  [entryPoints.web]
    address = ":80"

  [entryPoints.web.http.redirections.entryPoint]
    to = "websecure"
    scheme = "https"

  [entryPoints.websecure]
    address = ":443"

[certificatesResolvers.letsencrypt.acme]
  email = "<youremail>"
  storage = "/letsencrypt/acme.json"
  [certificatesResolvers.letsencrypt.acme.tlsChallenge]

[api]
  dashboard = false

[providers.docker]
  exposedByDefault = false
  network = "traefik-global-proxy" # this is really important when you have multiple networks on a single container. This will tell Traefik to always look for network traefik-global-proxy and not any other internal networks.

[http.services]
  [http.services.narvik.loadBalancer]
```
:::

Dans `traefik.toml`, il faut définir une adresse mail valide pour la génération des certificats Let's Encrypt.

## Mise à jour

Pour effectuer les mises à jour, il suffit :

1. Modifier la version des images dans le `compose.yaml`
   - Seulement si en retard par rapport à la version majeure disponible sur Github
     - [Release frontend](https://github.com/Narvik-app/frontend/releases)
     - [Release backend](https://github.com/Narvik-app/backend/releases)
2. `docker compose pull`
3. `docker compose stop && docker compose up -d`
   - La mise à jour de la base de données sera importée automatiquement au redémarrage du docker

::: warning Mise à jour depuis une version utilisant supervisor
Les consommateurs Messenger ne tournent plus dans le conteneur `php`.
Il faut ajouter les services `worker-high`, `worker` et `scheduler` (ainsi que le bloc `x-narvik-back` et le `healthcheck` de `database`) à votre `compose.yaml`, sinon les emails et imports ne seront plus traités.  
Les crons `bin/console clean` et `bin/console emailing:count:reset` peuvent être supprimés.
:::

::: code-group
```shell  [update.sh]
echo "🔀 Pulling latest images"
docker compose pull

echo "⚡️ Stopping docker"
docker compose stop

echo "🚀 Starting docker"
docker compose up -d

echo "✔ Docker running"
```
:::
