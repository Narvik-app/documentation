# Actions à effectuer après l'installation
Deux commandes ont été créées afin de faciliter l'étape d'initialisation de la base de données.

## Commande d'installation
L'installation se fait en ligne de commande.

Celle-ci va :
- Créer le schéma de base de données
- Créer un compte super admin
- Créer les paramètres globaux par défaut

```shell
bin/console install
```

## Commande d'installation OAuth
Cette commande, distincte de `install`, configure l'authentification :
- Génère les clés JWT (`config/jwt/private.pem` / `public.pem`)
- Crée le client OAuth `badger` (client public, sans secret, utilisé par le poste de pointage des présences)
- Crée le client OAuth `front` (client confidentiel, restreint aux grants `password` et `refresh_token`, utilisé par le frontend pour les connexions utilisateur)

```shell
bin/console install:oauth
```

Le secret du client `front` n'est affiché qu'une seule fois, à la création : reportez-le immédiatement dans `NUXT_OAUTH_CLIENT_ID` / `NUXT_OAUTH_CLIENT_SECRET` côté frontend (voir [Installation avec docker](./02.docker))  
Le client `badger` n'a pas de secret à reporter,
seul son identifiant (`NUXT_OAUTH_BADGER_CLIENT_ID=badger`) est nécessaire.

Cette commande est idempotente :
- la relancer répare un client `badger` mal configuré (secret présent, grants non restreints) sans perdre les sessions en cours ;
- elle ne touche jamais à un client `front` déjà existant (son secret, une fois haché, ne peut de toute façon plus être réaffiché).

Une fois ces commandes exécutées, vous pouvez [importer les données depuis itac/cerbère](/frontend/docs/import/fftir-itac).

## Tâches récurrentes

Les tâches récurrentes sont exécutées automatiquement par le conteneur `scheduler` (Symfony Scheduler), aucun cron n'est à configurer :

| Tâche                                        | Commande                           | Fréquence             |
|----------------------------------------------|------------------------------------|-----------------------|
| Nettoyage des données expirées               | `bin/console clean`                | Tous les jours à 3h00 |
| Remise à zéro du compteur d'emails des clubs | `bin/console emailing:count:reset` | Le 1er du mois à 3h15 |

Si le conteneur était arrêté au moment prévu, la tâche est rattrapée à son redémarrage.  
Les commandes peuvent aussi être lancées manuellement, la remise à zéro des emails ne s'effectue qu'une seule fois par mois.

Pour consulter le planning :

```shell
docker compose exec php bin/console debug:scheduler
```

## Sauvegardes des données
Voici un exemple de script de sauvegarde automatisée.


::: code-group
```shell  [backup.sh]
echo "Starting Narvik backup"

docker compose exec database sh -c 'pg_dumpall -c -U $POSTGRES_USER | gzip' > /backup/narvik/sql/dump_`date +%Y-%m-%d"_"%H_%M_%S`.sql.gz

echo "Backup finished"
```
:::

## Restauration des données
```shell
docker compose exec database sh -c 'psql -d $POSTGRES_DB -U $POSTGRES_USER -c "DROP SCHEMA IF EXISTS public CASCADE; CREATE SCHEMA public;"'

gunzip < dump_2024-04-28_01_00_01.sql.gz | docker compose exec -T database sh -c 'psql -d $POSTGRES_DB -U $POSTGRES_USER'
```
